## Open the visual prototype

M3 adds a separate [field and light reference laboratory](Docs/PHYSICS_M3.md), with a [passed build, rendering and regression gate](Docs/PHYSICS_M3_VALIDATION.md). Launch a built player with `--reference-lab` for an assumed 3D emitting torus, weighted tracers and a single-Schwarzschild optical control. The packaged `START_M3_REFERENCE_LAB.cmd` supplies this option. It uses a desktop screen interface and does not attach assumed gas to the SXS event.

Clone or download this repository, then open `BinaryBlackHole` in Unity Hub. The editable Unity source consists of `Assets`, `Packages` (including the lock file), and `ProjectSettings`; Unity recreates its ignored cache on first import. Generated Windows players and recordings are not stored in Git.

1. Install Unity Hub and Unity Editor **6000.3.25f1 (Unity 6.3 LTS)**, then sign in and activate a valid Unity license.
2. In Unity Hub, add the project folder `BinaryBlackHole` (not the repository root). Let Package Manager import the Universal Render Pipeline dependencies.
3. Open `Assets/DTET/Scenes/BinaryBlackHole_VisualStaging.unity` and press Play. The scene is also the sole enabled Build Settings scene. It now starts **paused**; Space or the wrist Play button begins the selected mode.
4. The scene opens in a first-person virtual visitor view. Right-drag to look, use WASD to move, Q/E to change height, Shift for faster movement, and the mouse wheel to move closer/farther. **V raises/lowers your virtual left wrist**. Left-click its world-space controls for play/pause, replay, speed, Start / Halfway / End, information, learning, dimming, or exit. Looking away leaves the wrist in its body-relative pose rather than pinning its menu to the screen. The glove, sleeve, cuff, and controls share a wrist transform.
5. **T** takes the visitor to the information panels; **H** opens and approaches the world-space learning board. Story / Graph / Model, scenario A / B / C, initial separation, playback rate, and the quick check remain there. A slider change is pending until **Apply Start**; applying creates a new paused physical scenario. H hides the board; F or Home returns to the exhibit. At the endpoint the markers give way to a **conceptual** remnant. Navigation and wrist inspection work while playback is paused and do not change event time.

Keyboard shortcuts: V raises/lowers the wrist, **O opens/closes wrist input options**, Space toggles pause/play, Esc pauses immediately, R resets, B dims the view, T approaches information, H approaches learning, F/Home returns to the event, and C toggles optional orbit inspection. **Default wheel movement is now 3× faster**; options provide independent mouse-look and scroll sensitivity sliders, local saved preferences and a reset-defaults button. See [input options](Docs/INPUT_OPTIONS.md). 1/2/3 select Story/Graph/Model on the learning board. Exit is on the wrist and learning board; in the Editor, use the Play toolbar to stop. An entrance plaque explains the emulation controls. The quick check is formative content, not a measured learning outcome.

The **lesson HUD** has spatial readout/graph/tutor panels and a wrist-mounted control canvas. U hides/restores the interface; V raises/lowers the wrist. In physical mode its km, orbital Hz, GW Hz and source seconds come from one immutable model snapshot. The graph is frequency versus source time, not detector strain. At the model cutoff physical frequencies become unavailable. The tutor remains a local scripted guide, not functional AI. [HUD background](Docs/PARTNER_HUD_INTEGRATION.md).

The scene uses the Input System and a runtime bootstrap for procedural, editable-in-code visuals. In physical mode the body centre positions are SI model outputs with a fixed displayed scale; marker sizes are enlarged and artistic annuli are hidden. The separate Storyboard mode retains layered gas artwork and an illustrative chirp. PHYSICS/STORYBOARD buttons on the learning board or P select the mode; Reverse/comma changes the direction of physical playback. A/B preserve the original 30+30-solar-mass lesson; C demonstrates unequal 20+40 masses. These are teaching configurations, not measured GW150914 parameters. No imported third-party art is required.

Stars no longer follow the camera: movement changes their viewing directions through finite-distance geometric parallax. **Live approximate lensing** shifts, splits and stretches background stellar images as the viewer moves. **J** pauses and aligns a fixed demonstration star behind a marker, **L** toggles bending for comparison, and **G** toggles thin-lens broken-ray guides. These commands are also on the wrist. Distances, lens strength, sizes and colours are authored exhibit values, not calibrated astronomical data. See [approximate lensing and its limits](Docs/APPROXIMATE_LENSING.md). Artistic disks remain in Storyboard mode; physical centre motion uses the bounded SI model. Calibrated relativistic redshift is deferred.

Future **dataset-backed strong-field binary optics** still needs suitable evolving metric data and a validated ray tracer; the thin-lens approximation does not supply it. `ObserverPhysicsBridge` provides a shared optics/clock provider boundary on the visitor, with an explicitly unavailable staging adapter. `AdmObserverPhysics.cs` supplies tested local metric-based proper-time/photon-energy mathematics, not a binary spacetime solver. A spatial clock comparison card is ready for future visitor and ideal far-away reference proper-time readings; it currently says **Not connected**. **K approaches that card; F returns to the exhibit.** Reset/seek/scenario changes and teleports invalidate incompatible history. See [optics and clocks](Docs/OPTICS_AND_CLOCKS.md) and the [dataset request](Docs/NUMERICAL_SPACETIME_DATA_REQUEST.md) for the future relativistic contract and data-access requirements.

The main binary exhibit's canvases are world-space; the separate M3 reference lab uses a camera-bound desktop HUD. In the main exhibit, desktop input emulates poses. `VirtualWristRig.BindTrackedWrist` is a transform-pose attachment boundary for later hardware integration; `ExhibitCameraRig.EmulatedInputEnabled` can disable keyboard/mouse head input. No headset SDK, controller/hand tracking, stereo build, teleport safety, or device comfort is claimed yet. Those require the selected headset/deployment target and real device tests. The mouse wheel moves the visitor, not the bodies or their separation.

## Source layout

- `BinaryBlackHole/`: Unity 6.3 LTS Universal 3D project, derived from Unity's included `com.unity.template.3d-cross-platform-17.0.14` template.
- `BinaryBlackHole/Assets/DTET/VisualPrototypeBootstrap.cs`: interactive visual composition and storyboard controls.
- `BinaryBlackHole/Assets/DTET/ExhibitCameraRig.cs`: independent orbit/fly navigation, tracking, zoom limits, and recoverable viewpoints.
- `BinaryBlackHole/Assets/DTET/VirtualWristRig.cs`: emulated raise/lower pose, visible glove/forearm/cuff, and tracked-wrist transform boundary.
- `BinaryBlackHole/Assets/DTET/VisualAssetFactory.cs`: reproducible geometry/material construction; no external texture dependency.
- `BinaryBlackHole/Assets/DTET/StellarSourceField.cs` and `StellarSource.cs`: fixed synthetic emitter objects and their shared approximate thin-lens image mesh, cached only when sources, lenses, observer and options are unchanged.
- `BinaryBlackHole/Assets/DTET/ObserverPhysicsBridge.cs` and `RelativityClockSnapshot.cs`: observer-attached provider boundary and proper-time comparison contract; no GR solver installed.
- `BinaryBlackHole/Assets/Resources/DTET/`: URP shaders for the exhibits, reference/generated volumes, synthetic sky, density samples, display mapping and illustrative optics. Kept in Resources so a player build can retain them without a serialized material reference.
- `BinaryBlackHole/Assets/DTET/InteractiveBinaryExhibit.cs`: combined desktop scenario, gas, optics and wrist presenter; the new interface and optical renderer are separate components beside it.
- `BinaryBlackHole/Assets/DTET/GeneratedFluidPlayer.cs`: cancellable background fluid generation, immutable timeline replay and bounded GPU field uploads.
- `BinaryBlackHole/Assets/DTET/ReducedBinaryExhibit.cs`: M4 quality launcher, numerical event bindings, continuous volume, diagnostic samples, radiation panel and desktop navigation.
- `BinaryBlackHole/Assets/DTET/Simulation/`: canonical pure C# model/session/graph/snapshots and tutor boundary, in the no-engine-reference `DTET.Simulation` assembly.
- `Staging/Simulation/`: portable project linking those same model sources.
- `Staging/Simulation.Tests/`: reproducible source tests; see `Staging/README.md`.

The partner's `InspiralDemo_Build.zip` was a Unity **6000.5.10f1 compiled Windows player**, with no editable `Assets`, `Packages`, `ProjectSettings`, or source scene. Its saved HUD layout and script metadata informed a source reconstruction in this 6.3 project; its binary assemblies were not imported. Please provide the editable partner project if direct asset/scene integration is desired.

## Evidence and limitations

Unity 6.3.25f1 import is now licensed and the visual C# compiles. The template's Input System 1.12.0 failed with `BuildTarget.ReservedCFE`, so the project uses Input System 1.17.0; the Editor resolves built-in URP 17.3.0. Unused Visual Scripting, Plastic collaboration, navigation and Timeline template packages were removed after first-import errors. The shared source model tests pass; M1 adds a separate opt-in built-player physical integration harness. See [M1](Docs/PHYSICS_M1.md) and `Scripts/Test-PhysicsMilestone.ps1`. The QA build menu is `DT-ET > Validate Assets and Build QA Player`; it checks all thirteen custom shaders and builds a Windows development player. Set `DTET_CAPTURE_PATH` and optionally `DTET_CAPTURE_VARIANT` (`Observe`, `Above`, `Side`, `Close`, `Story`, `Graph`, `Model`, `Endpoint`, or `ScenarioB`) before running that development player to execute automated UI/camera checks and write a screenshot. This harness is omitted from release builds. A headset/build target is only needed when deploying real device support, not for this pose-emulated exhibit.

`Hud` and `HudEnd` capture variants additionally show the partner HUD during the storyboard and at its conceptual endpoint; HUD command checks run in every capture variant.
